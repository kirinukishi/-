# RLAnything：AIエージェントの自己進化

ソース: https://www.youtube.com/watch?v=SwwTkZmbHrs

## 概要

プリンストン大学の論文。従来の強化学習は「方策（行動）」だけ学習し、報酬と環境は人間が固定していた。
RLAnythingは **方策・報酬モデル・環境の3つを同時に最適化** する。

結果: 8Bモデルがベンチマークで9.1%性能向上。AI最適化の報酬モデルが人間のラベル精度（80%）を超えた（85%）。

## 従来の強化学習の2つの問題

### 1. 報酬の疎さ
- 長いタスク（設計→コーディング→テスト→修正）で、最後の成否でしか報酬がもらえない
- 途中で良いコードを書いても強化されない
- マラソンでゴールでしかタイムが見れないようなもの

### 2. 教師のボトルネック
- 人間がAIの成長スピードに追いつけない
- AIが1秒で100個出力しても人間がチェックするのは無理
- 人間の評価能力がAI性能の上限を決めてしまう

## 3つのフィードバックループ

### 統合フィードバック（方策の改善）
- 途中経過の評価 + 最終結果を合わせて方策を改善
- 「テストは落ちたけど設計は良かった」→ 設計部分は褒めて学習

### 一貫性フィードバック（報酬モデルの改善）
- 最終結果から逆算して採点基準を修正
- 例: 「行数が短い方がいい」→ 実際は「コメントがあるコードの方が成功率が高い」と学ぶ

### 評価フィードバック（環境の調整）
- 成功率80%くらいが最も学習効率が良い
- 成功率が高すぎたら問題を難しくする
- ゲームの難易度調整と同じ

## Claude Code へのマッピング

| RLAnything | Claude Code の機能 |
|---|---|
| 方策（行動を決める） | LLM本体（System Prompt） |
| 報酬モデル（採点） | Post-tool-use Hook |
| 環境（問題設定） | CLAUDE.md / Memory ファイル |

### Post-tool-use Hook で取れる情報
- ツールの種類
- 入力パラメーター
- 実行結果
- エラー情報

### サブエージェントで役割分担
- メインエージェント → 作業
- サブエージェント → 採点・評価

## 実装の3フェーズ

### フェーズ1: 観測（今日からできる）
- Post-tool-use Hook でエージェントの全行動をログに取る
- どのファイルをどう編集したか、コマンド結果、エラー情報を memory.md に追記

### フェーズ2: フィードバック
- タスク完了後、成功/失敗を判定
- 成功 → 途中のどの判断が良かったか分析
- 失敗 → どこで間違えたか特定
- 構造化して記録: タスク名、結果、有効だったアクション

### フェーズ3: 自己進化
- 成功パターンを「スキル」として抽出し、次回のプロンプトに自動適用
- 例: 「Reactコンポーネントはテストを先に書いてから実装する」
- 動的難易度調整: 成功率80%超 → 抽象度を上げる / 20%未満 → 具体的な指示に変える
