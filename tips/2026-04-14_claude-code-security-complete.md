## Part 1: なぜセキュリティ対策が必要か

Claude Code は普通のChatGPTと違い、**パソコンのファイルを直接編集・コマンド実行・Web閲覧する**。
間違うと以下が起こる:

- ファイル書き換え/削除
- 機密情報の外部漏洩
- APIキー流出による数十万〜数百万円の請求
- プロンプトインジェクションで乗っ取り

実例: 2026年3月31日、AnthropicのClaude Codeソースコード51万行が流出。
同じ日にnx（週1億DL）がウイルス入り偽バージョンに乗っ取られた。
プロでさえ単純なヒューマンエラーで大事故を起こす。

## Part 3: セキュリティ設計の6原則（1970年代〜現代まで不変）

### 1. 最小権限の原則（Least Privilege）
> タスクに必要な最低限の権限だけ与える

- AIにパソコン全権限を渡さない
- クライアントにルート権限を渡さない/受け取らない
- **迷ったら権限を絞る**

### 2. 多層防御（Defense in Depth）
> 進撃の巨人の壁のように何重にも守る

```
APIキー保護の例:
層1: .envで分離
層2: .gitignoreで除外
層3: リポジトリ非公開
層4: 1Passwordで本体管理、.envは参照のみ
層5: IPアドレス制限
層6: 定期ローテーション
```

**100点の対策は存在しない。不完全な対策を重ねて安全になる。**

### 3. フェイルセーフデフォルト（Fail-safe Default）
> 迷ったら拒否が初期設定

- Claude Codeの確認に「Yes, Yes」連打は危険
- **迷ったらNo**
- GitHubのデフォルト公開設計そのものが問題

### 4. 攻撃面の最小化（Attack Surface Reduction）
> 入口の数を減らす

- 使ってないAIサービスのアカウント即削除
- 不要なパッケージを入れない
- 退職者のアカウント即停止
- WordPressプラグイン入れすぎ厳禁

### 5. 被害範囲の最小化（Blast Radius Reduction）
> 侵入された時に広がる範囲を絞る

- **APIキーを複数サービスで使い回し厳禁**
- 管理者アカウントで日常作業しない
- サービスごとに別のキーを発行

### 6. 職務分離（Separation of Duties）
> 申請する人と承認する人を分ける

- AIが実行、人間が承認
- Claude Codeの確認プロンプトはこの原則
- 「面倒だから全承認」は原則違反

## Part 4: Claude Codeで今すぐやるべき6対策

### 対策1: .envファイルをClaude Codeから見えなくする

**やり方:**
```
Claude Codeに「.envファイルを読み込めないように設定して」と言う
```
→ Claude Codeが自動で `deny rule` を作成してくれる

**手動の場合:** `.claude/settings.json` の `permissions.deny` に追加

⚠️ コメント欄の失敗例: 「設定後に本当に読めないかテストしたら、
中のAPIキーが見えた」という報告あり → 設定後に**別セッション**で動作確認必須

### 対策2: file-historyファイルを削除

Claude Codeは編集時に元内容を`~/.claude/file-history/`に**暗号化せず**自動バックアップ。
→ 最初にうっかり.envを編集させると、禁止設定後も過去のコピーが残る。

**やり方:**
```
Claude Codeに「file-historyフォルダの中身を削除して」と言う
→ 定期的に実行
```

### 対策3: Sandboxモードを有効化

**やり方:** ターミナルで `/sandbox` → オンに切替
- Macローカルで動かしてる場合はデフォルトOFFなので要注意
- 1分もかからない

### 対策4: CLAUDE.mdにセキュリティルールを書く

プロジェクト作成時の**最初**にやる習慣を。

**やり方:**
```
Claude Codeに「.env読まないってルール化しといて」
→ CLAUDE.md に自動で書き込み
```

### 対策5: テスト駆動開発（TDD）

**やり方:**
```
1. 「まずテストを書いて」
2. 「テストが通るようなコードを書いて」
```
→ バグがセキュリティホールになるリスクを低減

### 対策6: コンテキストの定期クリア

トークン = AIの体力。消費しすぎると判断精度が落ち、セキュリティ的にも危険に。

**目安: 40〜50%消費したらクリア準備**

**やり方:**
```
1. 「今の進捗をファイルに書き出して」
2. /clear でリセット（体力回復）
3. 書き出したファイルを読み込んで作業再開
```

## Part 5: .env運用のベストプラクティス

### 悪い例 ❌
```
OPENAI_API_KEY=sk-proj-actual-secret-key-here
```
直接書いてる。漏れたら即終了。

### 良い例1: 1Password参照方式
```
OPENAI_API_KEY=op://vault/openai/api-key
```
鍵の住所だけ書いて、本体は1Passwordに。

### 良い例2: dotenvx暗号化方式
```
# .env（暗号化済み）
OPENAI_API_KEY=encrypted:xxxxxxxxxxxxx
```
秘密鍵を持ってる人だけ復号できる。.envごとアップロードしても安全。

**注意:** 秘密鍵自体は絶対にアップロードしない。
