# 横断パターン：5本の動画から見えた共通原則

5本のYouTube動画（6TIPS, RLAnything, 動的フィルタリング, Excalidraw/Obsidian, Ralph Wiggum Loop）を横断して抽出した共通パターン。

## 原則1: 状態は頭の外に置け

全動画に共通する最も強いパターン。

| 動画 | どこに状態を置くか |
|---|---|
| 6TIPS | CLAUDE.md に失敗録を追記 → 次から同じミスを回避 |
| RLAnything | memory.md にログ・成功パターンを蓄積 |
| Obsidian CLI | Vault にメモを構造化して保存 |
| Ralph Wiggum | todo.json / progress.txt にタスク状態を外出し |

**なぜ**: LLMのコンテキストはセッションで消える。ファイルに書けば永続化＋git履歴で追跡可能。

**実践**: 学んだことは必ずファイルに書く。頭の中（会話履歴）に留めない。

---

## 原則2: フィードバックループを閉じろ

「やりっぱなし」では成長しない。全動画が「結果を次に活かす仕組み」を語っている。

| 動画 | ループの形 |
|---|---|
| 6TIPS | 失敗 → CLAUDE.md に記録 → 次回読み込み |
| RLAnything | 3種のフィードバックループ（統合・一貫性・評価） |
| 動的フィルタリング | 検索結果 → コード生成 → フィルタリング → 精度向上 |
| Ralph Wiggum | 実行 → ファイルに結果 → 次のループで読み込み |

**なぜ**: ループが閉じていないと同じ失敗を繰り返す。

**実践**: 「やった → 記録した → 次に読む」の3ステップを必ずセットにする。

---

## 原則3: 測定できないものは管理できない

「なんとなくいい感じ」を排除し、Yes/Noで判定できる基準を持つ。

| 動画 | 測定の例 |
|---|---|
| RLAnything | 成功率80%で難易度調整、複合スコアで報酬判定 |
| 動的フィルタリング | ベンチマーク2種で一貫した改善を確認 |
| Excalidraw/Obsidian | 権限スキップの7項目チェックリスト |
| Ralph Wiggum | 完了＝テスト全パス＋カバレッジ80%＋型エラー0 |

**なぜ**: AIは「完了しました」と嘘をつくことがある。証拠がなければ未完了。

**実践**: タスクには必ず「何をもって完了とするか」を数値で定義する。

---

## 原則4: 安全装置は事前に設計する

「危ないからやらない」ではなく「危ないから安全装置を設計する」。

| 動画 | 安全装置 |
|---|---|
| 6TIPS | 双子エージェント（攻撃者＋防御者でセキュリティ監査） |
| Excalidraw/Obsidian | --dangerously-skip-permissions は隔離環境限定（7項目チェック） |
| Ralph Wiggum | サーキットブレーカー（3回進捗なし→停止）、Stop Hook |

**なぜ**: 自律度を上げるほど暴走リスクも上がる。設計で担保する。

**実践**: 自動化する前に「止まる条件」を先に決める。

---

## 原則5: 小さく始めて段階的に難しくする

一気にやらない。全動画が「まず最小限から」と言っている。

| 動画 | 段階的アプローチ |
|---|---|
| RLAnything | フェーズ1（観測）→ フェーズ2（フィードバック）→ フェーズ3（自己進化） |
| RLAnything | 成功率80%超えたら難易度を上げる |
| 動的フィルタリング | 単純な検索→3つ以上の依存タスクで効果発揮 |
| Ralph Wiggum | MAX_ITERATIONS=10で試す → 感覚掴んでから拡大 |
| 6TIPS | 並列セッション: まず2-3個 → 慣れたら5-10個 |

**なぜ**: 大きく始めると失敗した時のデバッグが困難。

**実践**: 最初は手動＋小規模。うまくいったら自動化＋拡大。

---

## 原則6: 役割を分けろ

1つのエージェントに全部やらせない。専門家を分ける。

| 動画 | 役割分担 |
|---|---|
| 6TIPS | 攻撃者と防御者（双子エージェント） |
| 6TIPS | 並列5セッション（タスクごとに分割） |
| RLAnything | メインエージェント（作業） + サブエージェント（採点） |
| Ralph Wiggum | Sisyphus（指揮者） + Hephaestus（実装） + Oracle（原因究明）... |
| Excalidraw/Obsidian | マルチエージェント9人チーム（リサーチャー×3 + モニター + バグハンター...） |

**なぜ**: 1つに全部任せると、どこで詰まったか分からない。分けるとデバッグが容易。

**実践**: タスクが複雑なら「作業する人」と「チェックする人」を最低限分ける。

---

## 成長の段階マップ

5本の動画を並べると、成長の段階が見える：

```
Lv.1  手動メモ（6TIPS: CLAUDE.mdに失敗録を書く）
  ↓
Lv.2  構造化メモ（Obsidian CLI: 命名規則・タグ・フォルダで整理）
  ↓
Lv.3  自動ログ（RLAnything Phase1: Post-tool-use Hookでログ自動化）
  ↓
Lv.4  フィードバック（RLAnything Phase2: 成功/失敗から学びを抽出）
  ↓
Lv.5  自律ループ（Ralph Wiggum: 夜間に回して朝レビュー）
  ↓
Lv.6  自己進化（RLAnything Phase3: スキル抽出→プロンプト自動改善）
```

**今この環境はLv.1〜2。セッション跨ぎの手動ループでLv.2を固める段階。**
