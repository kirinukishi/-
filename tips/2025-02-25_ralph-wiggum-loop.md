# Ralph Wiggum Loop：AIエージェント自律ループ設計

ソース: https://www.youtube.com/watch?v=ruku-lzg4M0

## 概要

提唱者: Jeffrey Huntley。夜寝る前にAIにタスクを頼んで、朝起きたらテスト済みPRが立っている世界を実現する設計手法。

## 名前の由来

- シンプソンズのRalph Wiggum = 失敗しても全然気にしない、転んでも起き上がってまた同じことをやる
- 1980年代スラング「ralph」= 吐く → AIがコードを吐き続ける
- **失敗しても諦めない。結果が出るまで続ける。**

## 核心：1行ループ

```bash
while cat prompt.md | claude; do :; done
```

- `prompt.md` の内容をClaude Codeに渡して実行
- 終わったら同じことを繰り返す
- **プロンプトは同じだが、リポジトリの状態（コンテキスト）が毎回変わる**

### なぜ同じプロンプトで進むのか
1. 1回目: Claudeがコードを書く → ファイルに保存
2. 2回目: リポジトリの状態が変わっている → diffを見て次の作業を判断
3. 3回目: テストを走らせて結果を見て修正...

> 人間が繰り返してた「じゃあ次これやって」をループが肩代わりしているだけ。

## 設計思想

> 「確定的に悪い手順でも、非決定論的な世界では予測可能に失敗する方が制御しやすい」

- AIの出力は予測できない（非決定論的）
- でもループの構造は予測できる（決定論的）
- **制御できる部分とできない部分を分ける**

## 状態管理：LMの中ではなくファイルに置く

### なぜファイルに出すのか
- セッション終了で消えない
- gitで全履歴が残る（ロールバック可能）
- コンテキストウィンドウの汚染を回避
- 進捗の客観的な証拠になる（説明責任）

### 使うファイル例
- `todo.json` — タスクの進捗状態
- `progress.txt` — 試したこと・失敗のメモ

### コンテキスト汚染の回避
- 失敗の記録が会話履歴に溜まるとモデルがそっちに引っ張られる
- ループごとにセッションをリセットし、必要な情報だけファイルから読み込み直す
- **一晩寝てリフレッシュする感じ**

## 安全装置

### 1. Stop Hook（完了判定）

複合スコアで判断:
| シグナル | 点数 |
|---|---|
| JSON形式の完了シグナル | +50 |
| ファイルに変更がある | +20 |
| 完了キーワード | +10 |
| **合計70点以上** → 完了扱い |

### 2. サーキットブレーカー（暴走防止）

発動条件（数値で決めておく）:
- 連続3ループで進捗なし
- 同じエラーが5回連続
- ファイル権限エラーが2回続く

発動時の流れ:
1. Closed → **Open**（強制停止）
2. 冷却期間
3. Half-Open（テスト的に再開）
4. 問題なければ → Closed に戻る

**Open になったら人間に通知（Slack等）**

## マルチエージェント構成（発展形）

OpenCode の Sisyphus（シシュポス）の例:
- **Sisyphus**: オーケストレーター（仕事を振る指揮者）
- **Hephaestus**: 実装担当
- **Oracle**: 原因究明担当
- **Athena**: ドキュメント作成担当
- **Explorer**: コードベース探索担当

### Todo Continuation Enforcer
- タスクが未完了のまま放置されようとすると、強制的にtodoリストに戻される
- AIの「よくわからないから次のタスクに行こう」を防ぐ

## 実践ガイド

### 完了条件を測定可能にする（最重要）

❌ 悪い例: 「ログイン機能を実装する」
✅ 良い例:
- POST /api/login が 200 を返す
- JWTトークンが発行される
- パスワード間違いで 401

### タスクの粒度

- 1つのPRで出せるくらいの単位
- 単一コンテキストで完結するサイズ

### MAX_ITERATIONS の目安

| 規模 | 回数 |
|---|---|
| 小規模 | 5〜10 |
| 中規模 | 20〜30 |
| 大規模 | 50 |
| 50回超えて終わらない | → タスク分割すべき |

### 就寝前の実行例

1. タスク1: 認証機能の実装
2. タスク2: APIドキュメントの生成
3. タスク3: テストカバレッジの改善

→ 依存関係があるので**順番に回す**（並列ではない）
→ 朝起きたらコーヒー飲みながらレビュー

### 鉄則

> **証拠がない完了は未完了として扱う**
> ビルド成功ログ、テスト通過ログ、git diff、出力ファイルのどれかが必要

## 本質（3つの要素）

1. **反復** — ループで繰り返す
2. **外部状態** — ファイルに状態を持つ
3. **Exit条件** — ちゃんと止まる仕組み

> どれか1つ欠けても破綻する。三脚と同じで3本の足で支え合っている。
